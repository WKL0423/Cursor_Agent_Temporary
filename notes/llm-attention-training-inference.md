# 大模型：注意力、训练与推理

这份笔记把下面五个问题收在一起：self-attention 怎么算、为什么用 multi-head、训练分哪些阶段、各阶段的数据和数据量、推理时怎么加速和省显存。

注意力是模型的核心运算。训练决定这些权重从哪来、吃什么数据。推理时，同一套注意力变成显存和速度的瓶颈，优化手段都围绕权重和 KV cache。

---

## 1. Self-Attention 怎么计算

一句话：序列里每个位置用自己的 **Query** 去和所有位置的 **Key** 比相似度，再按这个权重把对应的 **Value** 加权求和。

### 输入和三个投影

设输入序列为 \(X \in \mathbb{R}^{n \times d}\)：\(n\) 是序列长度，\(d\) 是向量维度。每个位置 \(i\) 的向量是 \(x_i\)。

用三组可学习矩阵把 \(X\) 投影成 Query、Key、Value：

\[
Q = X W_Q,\quad K = X W_K,\quad V = X W_V
\]

\(W_Q, W_K \in \mathbb{R}^{d \times d_k}\)，\(W_V \in \mathbb{R}^{d \times d_v}\)。常见做法是 \(d_k = d_v = d / h\)（\(h\) 是头数）。

### 注意力权重

相似度用点积，再除以 \(\sqrt{d_k}\)，避免数值过大、softmax 过于尖锐：

\[
\text{scores} = \frac{Q K^\top}{\sqrt{d_k}} \in \mathbb{R}^{n \times n}
\]

\(\text{scores}_{ij}\) 表示位置 \(i\) 对位置 \(j\) 的关注程度。然后对每一行做 softmax：

\[
A = \mathrm{softmax}(\text{scores})
\]

第 \(i\) 行加起来为 1，表示位置 \(i\) 如何分配注意力。

### 加权求和

\[
\mathrm{Attention}(Q, K, V) = A V
\]

位置 \(i\) 的输出是所有位置 value 的加权平均：

\[
y_i = \sum_{j=1}^{n} A_{ij}\, v_j
\]

### 两个 token 的例子

设 \(d_k = d_v = 2\)，两个位置的 \(Q, K, V\) 为：

\[
Q = \begin{bmatrix} 1 & 0 \\ 0 & 1 \end{bmatrix},\quad
K = \begin{bmatrix} 1 & 0 \\ 1 & 0 \end{bmatrix},\quad
V = \begin{bmatrix} 1 & 2 \\ 3 & 4 \end{bmatrix}
\]

1. 点积：\(QK^\top = \begin{bmatrix} 1 & 1 \\ 0 & 0 \end{bmatrix}\)
2. 缩放（\(\sqrt{2} \approx 1.414\)）：\(\text{scores} \approx \begin{bmatrix} 0.707 & 0.707 \\ 0 & 0 \end{bmatrix}\)
3. 行 softmax：
   - 第 1 行两个分数相同，权重约为 \([0.5,\ 0.5]\)
   - 第 2 行两个分数都是 0，权重也是 \([0.5,\ 0.5]\)
4. 乘 \(V\)：两个位置的输出都是 \([2,\ 3]\)，也就是两个 value 的平均。

### 解码时的因果掩码

自回归生成时，位置 \(i\) 不能看未来。在 softmax 之前，把 \(j > i\) 的分数设成 \(-\infty\)，softmax 后这些位置权重为 0。

完整一层里，self-attention 的输出通常还会加残差、做 LayerNorm，再过前馈网络。

## 2. 为什么用 Multi-Head

一个 head 只能算一种关系。Multi-head 让同一层同时算多种关系，再把它们拼在一起。

Self-attention 的输出是 Value 的加权平均：每个位置只得到一份混合结果。Query 和 Key 也只有一套投影，相似度只有一种算法。句法、指代、词义会被压进同一次加权里。单头的平均会抑制模型同时关注不同子空间里的信息。

每一头有自己的 \(W_Q, W_K, W_V\)，等于在不同的低维子空间里各算一次注意力：

- 一头可以主要看相邻词（局部句法）
- 一头可以看句首或远距离词（长程依赖）
- 一头可以对齐「它」和前面的名词（指代）

这些结果先保持分开，最后用 \(W_O\) 再混合。混合发生在多种关系都已经算完之后。

\[
\mathrm{MultiHead}(X) = \mathrm{Concat}(\mathrm{head}_1, \ldots, \mathrm{head}_h)\, W_O
\]

常见设置是总维度不变：\(h\) 个头，每头维度 \(d / h\)。参数量和一次全维度的单头差不多，但多头明显更好。收益来自把表示拆进多个子空间、各自做注意力。

头数有折中。头太少，关系种类不够；头太多，每头维度太小，每个子空间表达能力变弱。原论文用 8 头。

## 3. 训练有哪些阶段

训练分成两大段：**预训练**让模型学会语言和知识，**后训练**让它按人的要求回答。

### 预训练（Pre-training）

在海量无标注文本上做下一词预测：给定前面的 token，预测下一个 token。

这一步学的是语法、事实、推理的原材料。模型还不会稳定地听指令。算力和数据几乎都花在这里。训练完得到基座模型（base model）。

有的团队还会做**继续预训练**：在代码、数学或某个领域的语料上接着训，把基座往特定能力上推。

### 监督微调（SFT）

用人工或模型写好的「指令 → 回答」做监督学习，让模型学会对话格式：按问题作答、按格式输出、拒绝不该答的内容。

SFT 让模型像一个助手。回答质量的上限受示范数据限制，模型主要是在模仿这些答案。

### 偏好对齐

SFT 之后，模型仍可能啰嗦、胡编或无视约束。这一步用「哪个回答更好」的偏好数据继续训。常见两条路：

- **RLHF**：先训一个奖励模型给回答打分，再用 PPO 等强化学习去提高奖励。InstructGPT / ChatGPT 走的是这条路。
- **DPO 及同类方法**：不单独训奖励模型，直接用偏好对（好答案 vs 差答案）更新策略模型，流程更短。

目标是让模型更符合人的偏好：有用、诚实、无害。

### 可验证奖励的强化学习

数学、代码这类任务有标准答案或测试用例，对错可以自动判定。用这种奖励做强化学习，模型会学会更长的推理过程。o1、R1 这一类推理模型的关键步骤就在这里，常常放在 SFT 之后，和偏好对齐并列或接在后面。

### 各阶段在学什么

| 阶段 | 数据 | 学到的东西 |
| --- | --- | --- |
| 预训练 | 网页、书、代码等原始文本 | 语言、知识、一般能力 |
| 继续预训练 | 领域语料 | 某一类知识或能力加强 |
| SFT | 指令和标准回答 | 按指令作答 |
| 偏好对齐 | 回答的好坏比较 | 更符合人的偏好 |
| 可验证奖励的 RL | 带自动判定的题目 | 数学、代码等推理 |

日常说的 Chat 模型，至少经过预训练和 SFT。要对齐人类偏好，再加上偏好对齐。强调长链推理的模型，通常还有可验证奖励的强化学习。

## 4. 数据与数据量

后训练要的是对的样本，预训练要的是够多、够干净的文本。量级差好几个数量级。

### 预训练

数据是网页、书籍、论文、代码、百科、数学文本，多语言混在一起。用之前要去重、去掉低质量和有害内容，并避开评测集，避免考题泄露进训练集。

按参数量看，Chinchilla 的计算最优大约是每个参数 20 个 token。现在的模型为了推理更便宜，会在这个比例上大幅超训。公开模型的实际用量：

| 模型 | 大约 token 数 |
| --- | --- |
| LLaMA 2 | 2 万亿 |
| LLaMA 3 | 15 万亿 |
| DeepSeek-V3 | 14.8 万亿 |
| Qwen2.5 | 18 万亿 |
| Qwen3 | 36 万亿 |

小模型超训更狠。同样 15 万亿 token，8B 大约是每个参数 1800 个 token，405B 只有几十个。

自己做实验：几十亿 token 就能把训练跑通。要一个能用的 1B–7B 基座，通常要几千亿到数万亿 token。网页一般占大头，代码、数学、书籍占比更高、重复采样更多。

继续预训练用领域语料，常见是几百亿到几千亿 token，并混入一部分通用文本，减轻遗忘。

### 监督微调（SFT）

数据是多轮对话，每条是「指令 → 标准回答」。任务要杂：问答、写作、代码、数学、工具调用、安全拒绝。格式必须和推理时的对话模板一致。

- 约 1 千到 1 万条高质量人工样本，就能看出会跟指令。LIMA 用约 1000 条证明了这一点。
- 做一个能用的开源对话模型，常见是 10 万到 100 万条。DeepSeek LLM 的 SFT 超过 100 万条；Tulu 3 的公开混合集约 94 万条。
- 再往上，脏数据会把模型带偏。数量让位于：答案是否正确、任务是否多样、是不是模型自己的薄弱项。

### 偏好对齐（RLHF / DPO）

数据是同一个问题下的一对回答，标出哪个更好。最好是当前模型自己采样出来的回答（on-policy），而不是别的模型留下的旧答案。一条提示配 4 到 8 个回答再排序，比只留一对更稳。

- 方法验证：约 1 万到 3 万对就够。InstructGPT 的奖励模型大约用了 3.3 万条比较。
- 实际对齐：约 6 万到 30 万对。UltraFeedback 约 6 万到 18 万对，Tulu 3 的偏好混合约 27 万对。
- 奖励模型本身不需要预训练那种规模，但标注标准要稳定，否则模型会去迎合噪声。

### 可验证奖励的强化学习

数据是题目加上能自动判对错的答案。数学看最终答案或证明检查器，代码看单元测试。没有唯一、可检查的标准，就不适合这一步。

题库通常是几万到几十万道，远小于预训练。每道题会采样很多条推理轨迹，所以消耗的 token 仍然很大。难度要有梯度：太简单学不到新东西，太难得不到正奖励。DeepSeek-R1 这类模型还会先用几千条长推理链做一次冷启动 SFT，再进入强化学习。

### 对照

| 阶段 | 一条数据长什么样 | 常见规模 | 更卡质量的地方 |
| --- | --- | --- | --- |
| 预训练 | 连续原文 | 数万亿 token | 去重、过滤、领域配比 |
| 继续预训练 | 领域原文 | 百亿–千亿 token | 和通用数据的混合比例 |
| SFT | 指令和标准答案 | 1 万–100 万条 | 答案对不对、任务全不全 |
| 偏好对齐 | 同一题的好坏回答 | 1 万–30 万对 | 比较是否来自当前模型、标准是否一致 |
| 可验证奖励的 RL | 题目 + 自动判定 | 几万–几十万题（轨迹可放大很多倍） | 难度梯度、判定是否可靠 |

## 5. 推理时怎么加速和省显存

推理分两段：**prefill**（一次吃完整段提示，算初始 KV）和 **decode**（每次生成一个新 token，反复读已有 KV）。瓶颈不一样：prefill 偏算力，decode 偏显存带宽。优化几乎都围绕 **模型权重** 和 **KV cache**。

### KV Cache：为什么又快又吃显存

自回归时，过去位置的 Key / Value 不变。把它们存下来，新 token 只算自己的 \(q, k, v\)，再和缓存里的 \(K, V\) 做注意力，避免每步重算整段历史。

代价是显存随「层数 × 头数 × 序列长度 × 精度」线性涨。长上下文、大 batch 时，KV cache 往往比权重更先顶满 GPU。

常见省 KV 的办法：

- **GQA / MQA**：多组 Query 共享一组 Key/Value，cache 体积按共享比例缩小（LLaMA 2/3、Qwen 等常用）。
- **量化 KV**：把 cache 存成 FP8 / INT8 / INT4，换一点精度换显存和带宽。
- **PagedAttention**：像虚拟内存一样分页管理 KV，减少碎片，提高并发占用率（vLLM）。
- **滑动窗口 / 局部注意力**：只保留最近一段 KV，丢掉更早的（或配合稀疏模式），限制长度上限。

### 权重：量化与更小的有效模型

权重常驻显存。把 FP16/BF16 压到更低精度，直接减体积、加快加载和矩阵乘：

| 手段 | 大致效果 | 注意点 |
| --- | --- | --- |
| INT8 / FP8 权重量化 | 体积约减半，吞吐常明显上升 | 校准或量化感知训练更稳 |
| INT4 / GPTQ / AWQ | 体积再减一截，消费级卡也能跑 7B–70B | 太狠会伤难题表现 |
| 稀疏 / MoE 路由 | 总参数大、每次激活少 | 需要专用实现才吃到加速 |

量化优先压线性层权重；注意力里的 softmax 仍多用较高精度，避免数值炸掉。

### 算子与调度：少搬数据、多并行

- **FlashAttention**：把注意力拆成块，在 SRAM 里算 softmax，少写全局显存里的 \(n \times n\) 分数矩阵。prefill 和训练侧收益大。
- **连续批处理（continuous batching）**：请求长短不一也能插空进同一批，GPU 少空转（vLLM、TensorRT-LLM 等）。
- **推测解码（speculative decoding）**：小模型先猜一串 token，大模型一次验证；猜对就少跑几次大模型前向。
- **张量 / 流水线并行**：单卡装不下时拆层或拆矩阵；通信要压住，否则 decode 更慢。

### 生成策略上的省算力

- 限制 `max_tokens`、提前 stop；能短答就短答。
- 能用前缀缓存（prefix / prompt cache）时，共用系统提示、工具说明，避免重复 prefill。
- 采样温度、top-p 本身不省显存，但减少无效重试等于省总时间。

### 一张对照表

| 瓶颈 | 典型症状 | 优先手段 |
| --- | --- | --- |
| 权重显存 | 模型加载失败、OOM | 权重量化、更小模型、多卡拆分 |
| KV 显存 | 长上下文或大 batch OOM | GQA、KV 量化、PagedAttention、缩短上下文 |
| Prefill 慢 | 长提示首 token 延迟高 | FlashAttention、前缀缓存、更短提示 |
| Decode 慢 | 每个新 token 都很慢 | 量化减带宽、连续批处理、推测解码、提高有效 batch |

推理优化的核心：能复用的别重算（KV、前缀），能变小的先变小（量化、GQA），能填满 GPU 的别空转（批处理与好的调度）。
